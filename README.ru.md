# Vaultix · Банковская транзакционная платформа

[English](README.en.md)

Vaultix — учебный проект о целостности денежных операций при сетевых повторах, параллельной обработке и отказах. Клиент видит свои счета и проводит внутренние переводы в RUB. Оператор открывает и блокирует счета, просматривает операции и аудит. Администратор управляет учебными пользователями и лимитами, запускает лабораторию.

## Запуск

```sh
docker compose up --build
```

Откройте [стенд](http://127.0.0.1:8080) или [Swagger UI](http://127.0.0.1:8080/api/docs). Compose ждёт готовности PostgreSQL, применяет Alembic к основной базе и базе лаборатории, затем добавляет синтетические данные. Логины `demo`, `recipient`, `operator`, `admin` используют локальное значение `Vaultix-demo-local`.

Переменные в [.env.example](.env.example) задают порт, пароль PostgreSQL и начальный пароль учебных пользователей. Для пароля PostgreSQL используйте символы, безопасные в URL. Начальный пароль применяется при первом создании пользователя. Стенд по умолчанию слушает только loopback. Сброс командой `docker compose down -v` удаляет все данные этого стенда.

```sh
docker compose exec backend alembic upgrade head
docker compose exec backend python -m vaultix.seed
docker compose stop
```

## Правила и API

Сумма передаётся целым числом копеек. Источник и получатель различаются, оба счёта активны, остаток достаточен, сумма укладывается в лимиты операции и UTC-дня. Клиент владеет источником. Оператор может провести перевод от имени клиента. Финансирование при открытии дебетует клиринговый счёт и кредитует клиентский. Перевод дебетует обязательство перед отправителем и кредитует обязательство перед получателем.

`POST /api/login` принимает `username` и `password`, возвращает сессионную cookie. `GET /api/accounts` показывает доступные счета. `POST /api/transfers` принимает `source_id`, `destination_id`, `amount_minor` и `currency`, а заголовок `Idempotency-Key` обязателен. HTTP 201 содержит ID проведённой операции. `GET /api/transfers/{id}` показывает проводки. Тот же ключ и тело возвращают сохранённый результат. Изменённое тело даёт HTTP 409. Идентификатор `X-Request-ID` связывает ответ с аудитом. Полный контракт в [OpenAPI](docs/api/openapi.json).

## Архитектура и код

Модульный монолит использует FastAPI, Pydantic, SQLAlchemy Core, Alembic и PostgreSQL 16. React, TypeScript, Vite, React Router и TanStack Query работают за nginx. Docker Compose поднимает сервисы, GitHub Actions проверяет сборку и тесты. Основные каталоги: `backend` — домен, сценарии, инфраструктура и API, `frontend` — интерфейс и Playwright, `tests` — pytest, `docs` — требования, BPMN и другие диаграммы, ADR и тестовые результаты, `scripts` — команды подготовки и проверки.

Остаток вычисляется из журнала. Отложенный триггер проверяет две встречные записи на commit. Отдельные триггеры защищают проведённые строки от изменений. При READ COMMITTED перевод сериализуется advisory-блокировкой ключа и блокировками счетов в порядке UUID. Лимиты читаются под shared lock. Проводки, результат ключа и аудит успеха фиксируются атомарно.

## Демонстрация

Войдите как `operator`, откройте расчётный счёт Ильи и скопируйте его ID. Войдите как `demo`, выполните перевод и откройте дебет и кредит в деталях. Затем как `admin` запустите «Два конкурентных списания» и «Ошибка и откат». Лаборатория показывает тела запросов, HTTP-ответы, снимки PostgreSQL и проверку инвариантов. Ещё шесть сценариев покрывают успех, нехватку средств, повтор, конфликт ключа, блокировку и лимит.

## Проверки, безопасность и статус

[Тест-план](docs/testing/plan.md) · [Результаты и запуск тестов](docs/testing/results.md) · [Модель угроз](docs/architecture/threats.md) · [Состояние проекта](docs/PROJECT_STATUS.md)

Пароли хешируются Argon2id. Сессии используют HttpOnly и SameSite, backend проверяет роль, владельца и Origin для изменяющих запросов. Конфигурация вне demo включает Secure cookie и отключает лабораторию. Лаборатория требует отдельной базы, принимает только фиксированные сценарии и доступна ADMIN. Аудит сохраняет идентификаторы и результаты.

Область применения — локальное портфолио на синтетических данных. Вне MVP внешние расчёты, FX, сторнирование, автоматизированная ротация секретов и нагрузочные SLO. Результаты ключей и данные лаборатории накапливаются до сброса. Возможные следующие этапы — корректирующие проводки, постраничная выборка курсором, сверка, регламент хранения данных и измерение нагрузки на журнал.
